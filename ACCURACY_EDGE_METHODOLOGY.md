# Accuracy Edge Monetization Methodology

## Objective

Determine whether a more accurate TOMATOES fair-value estimator can be monetized inside the tutorial-round Monte Carlo simulator, and if so, through which passive quoting mechanism.

This document is intentionally about mechanism design, not parameter tuning. The goal is to test distinct theories for how extra fair-value accuracy could improve market-making PnL.

## Ground Truth Used For Design

These assumptions come from the code and local data actually on disk:

- The simulator's TOMATOES book is generated by three bots:
  - Bot 1 outer wall quotes
  - Bot 2 inner quotes
  - Bot 3 rare single-sided near-FV quote
- The latent fair value is a random walk in simulator mode.
- Passive fills from simulated takers occur at the best price first.
- At the same price level, bot liquidity has queue priority over strategy liquidity.
- When the strategy penny-jumps inside the bot book, it becomes the best price and owns the front of the queue at that price.
- TOMATOES market-taker clips are small, mostly in the `2-5` range.

These facts imply:

- Small passive size changes only matter if they affect how much of the next taker clip gets filled.
- Overweighting one side is only valuable if the better-estimated side really has meaningfully better expected markout.
- If both sides already have large positive edge, reducing one side can easily cost more spread capture than it saves in adverse selection.

## Estimator Choice

All candidates in the lab trader use the same estimator family:

- Recover the Bot 2 bid/ask by removing the one-sided Bot 3 contamination when a third level is visible only on one side.
- Build a posterior interval for latent FV from the Bot 2 quote rule.
- Use the posterior center as the operational fair value.

This gives a much tighter latent-FV estimate than wallmid or fallback on the local inferred-truth sample. The experiment here is not whether the estimator is better. It is whether that extra accuracy can be monetized.

## Experimental Controls

The lab candidates keep the following fixed:

- EMERALDS strategy
- TOMATOES taking framework
- TOMATOES clearing framework
- TOMATOES passive quote prices

Only the passive quote sizing and side-allocation logic differs across candidates.

This isolates the monetization mechanism from unrelated strategy changes.

## Candidate Families

The 20 candidates are implemented in `/Users/alexsod/prosperity/bot2_edge_lab.py` and selected with the `EDGE_LAB_CANDIDATE` environment variable.

### Family 1: Directional Signal Tilts

- `balanced_mu`
  - Control. Uses the better fair value for prices, but keeps passive size balanced.
- `signal_linear`
  - Splits passive size by `posterior_center - best_mid`.
- `signal_narrow_only`
  - Same as `signal_linear`, but only when the posterior interval is narrow.

### Family 2: Edge-Difference Tilts

- `mean_edge_split`
  - Splits size by the difference in expected bid-versus-ask markout at the posted prices.
- `worst_edge_split`
  - Splits size by the difference in worst-case bid-versus-ask markout.
- `weak_side_haircut`
  - Keeps total passive budget fixed but directly haircuts the weaker side.

### Family 3: Confidence Or Total-Size Modulation

- `common_edge_scale`
  - Keeps sizes balanced but cuts total passive size when the common worst-case edge is weak.
- `width_confidence_scale`
  - Increases total passive size when the posterior interval is narrower.
- `wallmid_gap_guard`
  - Cuts total passive size when the new estimator strongly disagrees with wallmid.

### Family 4: Regime-Specific Bot Logic

- `phase_halfband`
  - Uses only which half of the Bot 2 interval is active.
- `spread13_specialist`
  - Only tilts when the Bot 2 spread implies the tight quarter-band regime.
- `bot3_contamination_filter`
  - Shrinks the side contaminated by a one-sided Bot 3 quote.
- `hybrid_regime_patch`
  - Composite rule:
    - contamination filter on one-sided Bot 3 rows
    - conviction buckets in the tight quarter-band regime
    - otherwise only a mild consensus tilt

### Family 5: Inventory-Coupled Monetization

- `inventory_shadow_mean`
  - Mean-edge split with a linear inventory shadow cost.
- `inventory_agree_only`
  - Uses estimator tilt only when it reduces inventory risk.
- `inventory_crossfade`
  - Fades from estimator-driven tilt near flat inventory to inventory-driven tilt near the soft limit.

### Family 6: Flow-Shape Aware Allocation

- `flow_capped_weak_side`
  - Caps the weaker side near one expected taker clip and gives the rest to the stronger side.
- `flow_capped_both`
  - Uses smaller total passive size when conviction is weak, larger budget when conviction is stronger.
- `discrete_conviction_buckets`
  - Maps edge strength into balanced, mild-split, or hard-split regimes.

### Family 7: Cross-Signal Confirmation

- `consensus_vwap_tilt`
  - Only tilts when the new estimator's side signal agrees with the old `vwap - wallmid` tilt direction.

## Why These Are Distinct

These are not 20 copies of one formula with slightly different numbers.

They test different hypotheses:

- Does the edge live in common directional signal or only in side-specific markout?
- Does narrower uncertainty mean "quote more" or just "tilt more"?
- Is the useful information mostly in special bot regimes such as spread-13 or one-sided Bot 3 contamination?
- Should accuracy gains be converted into more directional quoting, or only used when inventory permits?
- Is fill-limited monetization better modeled by expected taker clip size than by continuous confidence?
- Does the old `vwap - wallmid` effect act as a confirmation filter for the sharper estimator?

## Screening Stage

The screening stage exists to cut obvious losers before the expensive multi-seed benchmark.

Protocol:

- Run all 20 candidates plus the reference strategies.
- Use seed `20260406`.
- Use `250` Monte Carlo sessions.
- Rank candidates by mean total PnL.
- Keep the top `6` candidates.
- Always keep `balanced_mu` as a control if it did not finish in the top six.

Reasoning:

- A single-seed, moderate-session screen is enough to eliminate mechanisms that are clearly weaker than the field.
- The control candidate is kept even if it screens poorly because it answers whether the sharper estimator helps without any monetization logic.

## Full Benchmark Stage

After screening:

- Run the surviving candidates plus the reference strategies.
- Use seeds:
  - `20260406`
  - `20260407`
  - `20260408`
  - `20260409`
  - `20260410`
  - `20260411`
- Use `1000` Monte Carlo sessions per seed.

Primary comparisons:

- Candidate vs `baseline`
- Candidate vs `wallmid_sensitive`
- Candidate vs `fallback_sensitive`

Primary metrics:

- Mean total PnL across sessions
- Mean TOMATOES PnL across sessions
- Mean PnL delta versus each reference
- Win/loss/tie counts across seeds in the full benchmark summary

## Why This Benchmark Is Fair

- Every comparison within a seed uses the same simulator seed.
- All candidate strategies share the same base MM engine and differ only in monetization logic.
- References are rerun under the same simulator configuration used for the candidates.
- Screening is used only to reduce compute, not to declare winners.

## Interpretation Standard

The experiment should be interpreted conservatively:

- If a candidate beats `baseline` but not `wallmid_sensitive`, then the new mechanism is not enough to justify replacing the current stronger heuristic.
- If a candidate beats `wallmid_sensitive` but not `fallback_sensitive`, then the old fallback heuristic still captures something valuable that the new mechanism missed.
- If `balanced_mu` wins, then passive-size monetization was not necessary and the estimator alone was enough.
- If no candidate clearly wins, then the simulator is likely not paying much for extra fair-value accuracy through passive size control alone.
